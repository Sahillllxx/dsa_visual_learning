⏱️ Big O Notation

Understanding Time & Space Complexity — the first thing you MUST learn before solving any DSA problem.

📏

What is Big O Notation?

▼

Big O notation describes the upper bound of how an algorithm's time or space grows as the input size (n) increases. It answers: "In the worst case, how does my code scale?"

🎯 Striver's Analogy

Think of it like ordering food. If a restaurant says "delivery in 30 minutes," that's the worst case guarantee. It might come in 10 minutes, but you're guaranteed it won't take more than 30. That's Big O — the worst-case guarantee of your algorithm.

Why do we need it?

  • We can't measure time in seconds (hardware differs)
  • We need a hardware-independent way to compare algorithms
  • We count operations as a function of input size n
💡 Key Rule: We always drop constants and lower-order terms.
5n² + 3n + 7 → O(n²)
Because as n → ∞, only the highest power matters.

Three types of analysis:

NotationMeaningUsed For
O (Big O)Upper bound (worst case)Most commonly used ✓
Ω (Omega)Lower bound (best case)Rarely discussed
Θ (Theta)Tight bound (average)Academic settings

How to Calculate Time Complexity

▼

Striver's approach: Count the number of operations your code performs as a function of n.

Rule 1: Sequential statements → ADD

O(n) + O(n) = O(n) for (i = 0; i < n; i++) { ... } // O(n) for (j = 0; j < n; j++) { ... } // O(n) // Total: O(n) + O(n) = O(2n) = O(n)

Rule 2: Nested loops → MULTIPLY

O(n) × O(n) = O(n²) for (i = 0; i < n; i++) { // O(n) for (j = 0; j < n; j++) { // O(n) ... } } // Total: O(n) × O(n) = O(n²)

Rule 3: Drop constants

Constants don't matter O(3n² + 5n + 100) → O(n²) O(1000n) → O(n) O(n/2) → O(n)

Rule 4: Drop lower-order terms

Keep only dominant term O(n² + n) → O(n²) O(n³ + n² + n) → O(n³) O(2ⁿ + n³) → O(2ⁿ)

Rule 5: Loops that halve → O(log n)

O(log n) while (n > 0) { n = n / 2; // or n >>= 1 } // Runs log₂(n) times
⚠️ Common Mistake: Don't just count loops! A loop running from 0 to n with i += 2 is still O(n), not O(n/2). We drop the constant.

All Time Complexities Explained

▼

O(1) — Constant Time Excellent

Same number of operations regardless of input size. Direct access, math formulas.

// Accessing array element by index int x = arr[5]; // Always 1 operation // Arithmetic formula int sum = n * (n + 1) / 2; // No matter how big n is

O(log n) — Logarithmic Excellent

Input is halved each step. Binary search is the classic example.

// Binary Search while (low <= high) { int mid = (low + high) / 2; if (arr[mid] == target) return mid; else if (arr[mid] < target) low = mid + 1; else high = mid - 1; } // For n = 10⁹, only ~30 iterations!

O(√n) — Square Root Good

Checking divisors, prime checking.

// Check if n is prime for (int i = 2; i * i <= n; i++) { if (n % i == 0) return false; } // For n = 10⁹, only ~31623 iterations

O(n) — Linear Good

Visit every element once. Single loops, linear search, traversals.

// Find max element int max = arr[0]; for (int i = 1; i < n; i++) { if (arr[i] > max) max = arr[i]; } // Visits each element exactly once

O(n log n) — Linearithmic Good

Efficient sorting algorithms. This is the best possible for comparison-based sorting.

// Merge Sort, Quick Sort (avg), Heap Sort Arrays.sort(arr); // O(n log n) // Why? You divide n elements into log n levels // At each level, you do O(n) work → n × log n

O(n²) — Quadratic Decent

Nested loops over the same array. Bubble sort, checking all pairs.

// Bubble Sort for (int i = 0; i < n; i++) { for (int j = 0; j < n - i - 1; j++) { if (arr[j] > arr[j+1]) swap(arr[j], arr[j+1]); } }

O(n³) — Cubic Slow

Three nested loops. Matrix multiplication, Floyd-Warshall.

// Matrix Multiplication (naive) for (i = 0; i < n; i++) for (j = 0; j < n; j++) for (k = 0; k < n; k++) C[i][j] += A[i][k] * B[k][j];

O(2ⁿ) — Exponential Very Slow

Recursive solutions without memoization. Subsets, Fibonacci (naive).

// Fibonacci without memoization int fib(int n) { if (n <= 1) return n; return fib(n-1) + fib(n-2); // 2 calls each time! } // For n=40, this takes ~1 billion operations 😱

O(n!) — Factorial Extremely Slow

Generating all permutations, brute force TSP.

// Generate all permutations void permute(arr, l, r) { if (l == r) print(arr); for (i = l; i <= r; i++) { swap(arr[l], arr[i]); permute(arr, l+1, r); swap(arr[l], arr[i]); } } // 10! = 3,628,800 | 12! = 479,001,600 | 15! = 💀

Space Complexity

▼

Space complexity measures how much extra memory your algorithm uses (excluding input). Striver emphasizes: always think about auxiliary space.

🎯 Striver's Analogy

Think of it as desk space. The input papers are already on your desk — space complexity is about how many extra sticky notes you need to solve the problem.

SpaceMeaningExample
O(1)Constant extra spaceSwapping variables, counters
O(log n)Recursion stack (divide)Binary search recursive, merge sort stack
O(n)Linear extra spaceHashMap, copying array, recursion depth n
O(n²)2D matrixDP table, adjacency matrix

Input Space vs Auxiliary Space

// Input space: O(n) for the array itself // Auxiliary space: what EXTRA memory we use // Example 1: O(1) auxiliary space int sum = 0; for (int i = 0; i < n; i++) sum += arr[i]; // Only 'sum' and 'i' → O(1) extra // Example 2: O(n) auxiliary space int[] temp = new int[n]; // Created extra array! for (int i = 0; i < n; i++) temp[i] = arr[n-1-i];

Recursion Stack Space

// This uses O(n) stack space! void print(int n) { if (n == 0) return; System.out.println(n); print(n - 1); // n calls stacked } // Binary search recursion uses O(log n) stack space int bs(int[] arr, int lo, int hi, int target) { if (lo > hi) return -1; int mid = (lo + hi) / 2; // Only ONE recursive call → halves each time → O(log n) }
⚠️ Striver's Warning: In interviews, when they say "solve it in O(1) space," they mean auxiliary space. The input array doesn't count. But modifying the input array is generally allowed unless stated otherwise.

Common Mistakes (Striver's Tips)

▼
❌ Mistake✅ Reality
"O(2n) is different from O(n)"No! Drop constants. O(2n) = O(n)
"HashMap lookup is always O(1)"Amortized O(1). Worst case O(n) with collisions
"Recursion is always slow"Recursion + memoization can be O(n)
"O(n + m) = O(n)"Only if m ≤ n. Keep both if independent
"Sorting is always O(n log n)"Counting sort can be O(n+k) for small ranges
"O(log n) base doesn't matter"Correct! log₂n and log₁₀n differ by a constant
💡 Striver's Interview Tip: When the interviewer asks time complexity, state it clearly: "The time complexity is O(n log n) because I'm sorting the array, and the space complexity is O(1) since I'm sorting in-place." Always explain WHY.

Recursion Time Complexity

▼

Striver's approach: Draw the recursion tree and count total nodes.

Linear Recursion → O(n)

f(n) → f(n-1) → f(n-2) → ... → f(0) // n calls in a straight line = O(n) time, O(n) space

Binary Recursion → O(2ⁿ)

// Each call spawns 2 more calls f(4) / \ f(3) f(2) / \ / \ f(2) f(1) f(1) f(0) // Total nodes ≈ 2ⁿ

Divide & Conquer → O(n log n)

// Merge Sort recurrence: T(n) = 2T(n/2) + O(n) // Level 0: 1 problem of size n → O(n) work // Level 1: 2 problems of size n/2 → O(n) work // Level 2: 4 problems of size n/4 → O(n) work // ...log n levels × O(n) work each = O(n log n)
💡 Master Theorem (simplified by Striver):
T(n) = aT(n/b) + O(nᶜ)

• If log_b(a) > c → O(n^(log_b(a)))
• If log_b(a) = c → O(nᶜ × log n)
• If log_b(a) < c → O(nᶜ)

🎯 Striver's Quick Sort Story

Quick Sort is O(n²) worst case (already sorted array with bad pivot), but O(n log n) on average with random pivots. That's why in practice it's faster than Merge Sort — better cache performance + in-place. But in interviews, mention the worst case!
