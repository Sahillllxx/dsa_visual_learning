Before we start — why does sorting matter? Almost every problem in DSA uses sorting as a building block — Two Sum, 3Sum, Merge Intervals, Meeting Rooms… If you don't understand sorting deeply, you'll always be guessing. Master this and your problem-solving speed doubles.

📌 What is Sorting?

Sorting is the process of arranging elements of a list in a certain order (typically ascending or descending). The input is an unsorted array [5, 2, 8, 1, 9] and the output is [1, 2, 5, 8, 9].

🗂️ Types of Sorting Algorithms
  • Comparison-based: Compare elements to decide order — Bubble, Selection, Insertion, Merge, Quick
  • Non-comparison-based: Use properties of data — Counting Sort, Radix Sort (can be O(n)!)
  • In-place: Uses O(1) extra space — Selection, Bubble, Insertion, Quick
  • Stable: Equal elements maintain original order — Bubble, Insertion, Merge
1
Selection Sort
Find the minimum, place it at the correct position
Time — Best
O(n²)
Time — Worst
O(n²)
Space
O(1)
Stable?
❌ No

Think of it this way — you have an array and you want to sort it. In each pass, find the minimum element from the unsorted part and put it in its correct position. That's it! After pass 1, index 0 is sorted. After pass 2, index 0 and 1 are sorted. And so on...

💡 Intuition — Step by Step
1
Start from index i = 0. Assume the minimum is at index i.
2
Traverse from i+1 to n-1, find the actual minimum element's index.
3
Swap the minimum element with the element at index i.
4
Increment i and repeat until the array is sorted.

C++ / Java / Python 
// ── Selection Sort ──
void selectionSort(int arr[], int n) {
    for (int i = 0; i < n - 1; i++) {
        int minIdx = i;          // Assume min is at i
        for (int j = i + 1; j < n; j++) {
            if (arr[j] < arr[minIdx])
                minIdx = j;      // Found a smaller element
        }
        swap(arr[i], arr[minIdx]); // Place min at correct position
    }
}

// Time: O(n²) — always, even for sorted array (no optimization)
// Space: O(1) — in-place
// Stable: NO — swap can change relative order of equal elements
2
Bubble Sort
Adjacent swaps — largest element "bubbles up" each pass
Time — Best
O(n)
Time — Worst
O(n²)
Space
O(1)
Stable?
✅ Yes

Bubble Sort is the simplest sorting algorithm. In each pass, we compare adjacent elements and swap if they're in wrong order. After each pass, the largest unsorted element "bubbles up" to its correct position at the end. The KEY optimization — if no swaps happen in a pass, the array is already sorted — break early! This gives O(n) for already sorted arrays.

💡 Intuition — Step by Step
1
Run outer loop from i = 0 to n-1. In each pass, the last i elements are already sorted.
2
Inner loop: compare arr[j] and arr[j+1]. If arr[j] > arr[j+1], swap them.
3
Use a didSwap flag — if no swap in a complete pass, array is sorted, break!

// ── Bubble Sort (Optimized) ──
void bubbleSort(int arr[], int n) {
    for (int i = 0; i < n - 1; i++) {
        bool didSwap = false;           // 🔑 Key optimization
        for (int j = 0; j < n - 1 - i; j++) {
            if (arr[j] > arr[j + 1]) {
                swap(arr[j], arr[j + 1]);
                didSwap = true;
            }
        }
        if (!didSwap) break;             // Already sorted → O(n)
    }
}

// Best Case: O(n) — when array is already sorted (didSwap stays false)
// Worst Case: O(n²) — reverse sorted array
// Stable: YES — only swap when arr[j] > arr[j+1], equal stays
3
Insertion Sort
Build sorted portion one element at a time — like sorting cards in hand
Time — Best
O(n)
Time — Worst
O(n²)
Space
O(1)
Stable?
✅ Yes

Think of how you sort playing cards. You pick one card at a time and insert it in the right position among the already sorted cards in your hand. That's exactly Insertion Sort! It's brilliant for nearly-sorted arrays because in best case it's O(n). Also used as part of Timsort (what Python's sort() uses internally)!

💡 Intuition — Step by Step
1
Start from i = 1 (single element is always sorted).
2
Pick element at i as key. Compare it with elements before it (j = i-1 downto 0).
3
While arr[j] > key, shift arr[j] one position right (arr[j+1] = arr[j]).
4
Place key at arr[j+1] — its correct position in the sorted portion.

C++ 
// ── Insertion Sort ──
void insertionSort(int arr[], int n) {
    for (int i = 1; i < n; i++) {
        int key = arr[i];     // Element to insert
        int j = i - 1;
        // Shift elements greater than key one position ahead
        while (j >= 0 && arr[j] > key) {
            arr[j + 1] = arr[j];
            j--;
        }
        arr[j + 1] = key;     // Place key at correct position
    }
}

// Best Case: O(n) — already sorted, inner while loop never executes
// Worst Case: O(n²) — reverse sorted, shifts every time
// GREAT for: small arrays, nearly sorted data, online sorting
4
Merge Sort
Divide & Conquer — split, sort, merge
Time — Best
O(n log n)
Time — Worst
O(n log n)
Space
O(n)
Stable?
✅ Yes

This is where the fun begins! Merge Sort follows Divide and Conquer — the most powerful technique in algorithms. The idea is simple: "If I can't solve the whole problem, break it into smaller problems, solve them, then combine!" Recursively divide the array into halves until single elements, then merge them back in sorted order. O(n log n) guaranteed — no bad cases!

💡 Intuition — Divide & Conquer
1
DIVIDE: Find mid = (low + high) / 2. Recursively sort left half [low..mid] and right half [mid+1..high].
2
BASE CASE: If low >= high (single element), return — a single element is always sorted!
3
MERGE: Take two sorted halves and merge them into one sorted array using two pointers.
4
In merge: pick smaller of arr[i] vs arr[j], add to temp, advance pointer. Copy remaining elements.

// ── Merge Sort ──
void merge(int arr[], int low, int mid, int high) {
    vector<int> temp;
    int i = low, j = mid + 1;
    while (i <= mid && j <= high) {
        if (arr[i] <= arr[j]) temp.push_back(arr[i++]);
        else                  temp.push_back(arr[j++]);
    }
    while (i <= mid)  temp.push_back(arr[i++]);  // Remaining left
    while (j <= high) temp.push_back(arr[j++]);  // Remaining right
    for (int k = low; k <= high; k++)
        arr[k] = temp[k - low];
}

void mergeSort(int arr[], int low, int high) {
    if (low >= high) return;       // Base case
    int mid = (low + high) / 2;
    mergeSort(arr, low, mid);       // Sort left half
    mergeSort(arr, mid + 1, high);  // Sort right half
    merge(arr, low, mid, high);     // Merge sorted halves
}

// Time: O(n log n) — always. log n levels × O(n) merge per level
// Space: O(n) — temp array in merge
// Stable: YES — we use <= in merge (equal goes left first)

⚡ Why O(n log n)? Think of the recursion tree. There are log n levels (we keep halving). At each level, the total work done for all merges is O(n). So total = log n × n = O(n log n). Beautiful math!

5
Quick Sort
Pick a pivot, partition around it, recurse
Time — Best
O(n log n)
Time — Worst
O(n²)
Space
O(log n)
Stable?
❌ No

Quick Sort is the most used sorting algorithm in practice. It's in-place (O(log n) stack space) and has great cache performance. The idea: pick a pivot, put all smaller elements to its left, all larger to its right (this is called PARTITION). Then recursively sort the left and right parts. The pivot is now in its FINAL sorted position!

💡 Partition — The Heart of Quick Sort
1
Pick pivot (we'll use the first element as pivot). Use two pointers: i = low+1, j = high.
2
i pointer: Move right while arr[i] <= pivot (i should stop at element > pivot).
3
j pointer: Move left while arr[j] > pivot (j should stop at element <= pivot).
4
If i < j: swap arr[i] and arr[j]. Repeat until i >= j.
5
Swap pivot (arr[low]) with arr[j]. Now pivot is at its correct final position!

// ── Quick Sort ──
int partition(int arr[], int low, int high) {
    int pivot = arr[low];     // Pivot = first element
    int i = low + 1;
    int j = high;

    while (true) {
        while (i <= high && arr[i] <= pivot) i++;  // Move i right
        while (j > low  && arr[j] > pivot)  j--;  // Move j left
        if (i < j) swap(arr[i], arr[j]);
        else break;
    }
    swap(arr[low], arr[j]);   // Place pivot at correct position
    return j;                 // Pivot's final index
}

void quickSort(int arr[], int low, int high) {
    if (low >= high) return;
    int pIdx = partition(arr, low, high);
    quickSort(arr, low, pIdx - 1);   // Sort left of pivot
    quickSort(arr, pIdx + 1, high);  // Sort right of pivot
}

// Avg: O(n log n) | Worst: O(n²) — when pivot is always min/max
// Worst case avoided by random pivot selection in practice!
⚠️ When does Quick Sort give O(n²)?

When the pivot is always the smallest or largest element — like sorting an already-sorted array with pivot = first element. This creates an unbalanced partition: one side has n-1 elements, other has 0. That's n levels × O(n) work = O(n²).


Fix: Use random pivot, or median-of-three pivot selection. In practice, Quick Sort with good pivot choice beats Merge Sort due to better cache locality!

Counting Sort
Non-comparison sort — use frequency counting, O(n+k)
Time
O(n + k)
Space
O(k)
Stable?
✅ Yes
Range
Small k only

Here's where we break the O(n log n) barrier — but with a catch! Counting Sort doesn't COMPARE elements at all. Instead, it counts how many times each value appears, then reconstructs the sorted array from counts. O(n + k) where k = range of values. But it only works for integers with a small range.

💡 Intuition — Step by Step
1
Find max element in array. Create count array of size max+1, initialized to 0.
2
Count frequencies: For each element x, increment count[x].
3
Reconstruct: For i from 0 to max, add i to output count[i] times.
📝 Dry Run — arr = [4, 2, 2, 8, 3, 3, 1]
Input: [4, 2, 2, 8, 3, 3, 1]

Count Array (index = value):
Index:  0  1  2  3  4  5  6  7  8
Count: [0, 1, 2, 2, 1, 0, 0, 0, 1]

Reconstruct: 1×1, 2×2, 3×2, 4×1, 8×1

Output: [1, 2, 2, 3, 3, 4, 8]  ✓
C++ 
// ── Counting Sort ──
void countingSort(vector<int>& arr) {
    int maxVal = *max_element(arr.begin(), arr.end());
    vector<int> count(maxVal + 1, 0);

    for (int x : arr)
        count[x]++;            // Count occurrences

    int idx = 0;
    for (int i = 0; i <= maxVal; i++)
        while (count[i]-- > 0)
            arr[idx++] = i;    // Rebuild sorted array
}

// Time: O(n + k) where k = max value in array
// Space: O(k) for count array
// Use when: integers, small range (e.g. 0 to 1000)
// DON'T use when: large range, negative numbers (need offset), floats

Radix Sort
Sort digit by digit — from least significant to most significant
Time
O(d × (n+k))
Space
O(n + k)
Stable?
✅ Yes
d = digits
k = 10

Radix Sort takes Counting Sort further — it handles large numbers by sorting one digit at a time, from the rightmost digit (units) to leftmost (highest place value). Key insight: use stable Counting Sort as a subroutine for each digit position. For 32-bit integers, d = 10 digits, so it's effectively O(n)!

📝 Dry Run — arr = [170, 45, 75, 90, 802, 24, 2, 66]
After sorting by units digit:  [170, 90, 802, 2, 24, 45, 75, 66]
After sorting by tens digit:   [802, 2, 24, 45, 66, 170, 75, 90]
After sorting by hundreds digit: [2, 24, 45, 66, 75, 90, 170, 802] ✓

Note: Each step uses STABLE sort — so relative order from
previous step is preserved for equal digits.
C++ 
// ── Radix Sort ──
void countSort(vector<int>& arr, int exp) {
    int n = arr.size();
    vector<int> output(n), count(10, 0);

    for (int i = 0; i < n; i++)
        count[(arr[i] / exp) % 10]++;          // Count current digit

    for (int i = 1; i < 10; i++)
        count[i] += count[i - 1];              // Prefix sum (for stable sort)

    for (int i = n - 1; i >= 0; i--) {       // Build output (RTL for stability)
        int d = (arr[i] / exp) % 10;
        output[--count[d]] = arr[i];
    }
    arr = output;
}

void radixSort(vector<int>& arr) {
    int maxVal = *max_element(arr.begin(), arr.end());
    for (int exp = 1; maxVal / exp > 0; exp *= 10)
        countSort(arr, exp);
}

// d = number of digits, k = 10 (decimal)
// Time: O(d × n) ≈ O(n) for fixed-size integers
