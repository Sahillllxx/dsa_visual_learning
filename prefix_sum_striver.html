Section 01

Why do we even need Prefix Sum? 🤔

Bhai, suno! Whenever you have multiple range sum queries on the same array, doing brute force is a crime. You're re-calculating the same things again and again. Let me show you why that hurts — and how prefix sum fixes it in one shot.

Imagine you have an array and someone asks you Q queries like: "Give me the sum of elements from index L to R."

🐢 Brute Force Approach

For each query, you run a loop from L to R and add everything up.

Time per Query
O(N)
Loop through L to R each time
Total for Q queries
O(N × Q)
Can be 10⁵ × 10⁵ = 10¹⁰ — TLE!
N = 10⁵ and Q = 10⁵ → Brute force does 10 billion operations. That's a guaranteed Time Limit Exceeded on any judge.

🚀 Prefix Sum Approach

Precompute once in O(N). Answer every single query in O(1). That's the magic.

Preprocessing
O(N)
Build the prefix array once
Each Query
O(1)
Just a subtraction formula!
Prefix Sum is the classic Precomputation technique. Trade O(N) space to get O(1) query time. One of the most important tricks in competitive programming.
Section 02

Building the Prefix Sum Array 🏗️

The idea is dead simple. prefix[i] stores the sum of all elements from index 0 to i. That's it. Once you have this, any range sum is just two lookups away.

Formal Definition

Prefix Array Formula
prefix[0] = arr[0]
prefix[i] = prefix[i-1] + arr[i]    for i ≥ 1

What does prefix[i] mean?

prefix[i] = sum of arr[0] + arr[1] + ... + arr[i]
It's the running total from the beginning up to index i. Think of it like a bank balance — prefix[i] is your total money after day i.
Section 03

Answering Range Queries in O(1) ⚡

Now comes the most satisfying part. Once prefix array is built, to get sum from L to R, we don't loop — we just do ONE subtraction. Let me walk you through the derivation, because understanding the "why" is more important than memorising the formula.

Derivation — Don't Just Memorise!

We know:

What we know
prefix[R] = arr[0] + arr[1] + ... + arr[L-1] + arr[L] + ... + arr[R]

prefix[L-1] = arr[0] + arr[1] + ... + arr[L-1]

Subtract the second from the first:

Range Sum Formula
sum(L, R) = prefix[R] - prefix[L-1]

Special case: if L == 0 → sum = prefix[R]
Think of it this way: prefix[R] has "too much" — it includes elements before L. So we subtract prefix[L-1] to strip them off.

Edge Case — L = 0

When L = 0, there's no prefix[L-1] = prefix[-1]. Handle it separately: sum = prefix[R]. Always check this in interviews!

Section 05

Clean Java Implementation 💻

Now write the cleanest possible Java. In interviews, always write modular code — one function to build, one to query. Don't put everything in main.

Method 1 — Separate prefix array

Java
public class PrefixSum {

    // O(N) — Build prefix sum array
    public static int[] buildPrefix(int[] arr) {
        int n = arr.length;
        int[] prefix = new int[n];
        prefix[0] = arr[0];
        for (int i = 1; i < n; i++) {
            prefix[i] = prefix[i - 1] + arr[i];
        }
        return prefix;
    }

    // O(1) — Range sum query [L, R] (0-indexed)
    public static int query(int[] prefix, int L, int R) {
        if (L == 0) return prefix[R];
        return prefix[R] - prefix[L - 1];
    }

    public static void main(String[] args) {
        int[] arr = {3, 1, 4, 1, 5, 9, 2, 6};
        int[] prefix = buildPrefix(arr);

        // Query: sum from index 2 to 5 = 4+1+5+9 = 19
        System.out.println(query(prefix, 2, 5)); // Output: 19

        // Query: sum from index 0 to 3 = 3+1+4+1 = 9
        System.out.println(query(prefix, 0, 3)); // Output: 9
    }
}

Method 2 — In-place (space optimized)

Be careful! In-place modifies the original array. Only do this if you don't need the original array later.
Java
// Mutates arr itself — arr[i] becomes prefix[i]
public static void buildInPlace(int[] arr) {
    for (int i = 1; i < arr.length; i++) {
        arr[i] += arr[i - 1];
    }
}
// Same query function works on mutated arr

Method 3 — 1-indexed (safer for competitive coding)

Java
// prefix[0] = 0 as sentinel — avoids L-1 edge case entirely!
public static int[] buildPrefix1Indexed(int[] arr) {
    int n = arr.length;
    int[] prefix = new int[n + 1]; // size n+1
    for (int i = 1; i <= n; i++) {
        prefix[i] = prefix[i - 1] + arr[i - 1];
    }
    return prefix;
}

// Query [L, R] (0-indexed in original array)
public static int query1(int[] prefix, int L, int R) {
    // No special case needed! prefix[0] = 0 handles it.
    return prefix[R + 1] - prefix[L];
}
In competitive programming, always prefer the 1-indexed approach. It eliminates the L==0 edge case completely with a sentinel zero at prefix[0].
Time Complexity
O(N + Q)
O(N) build + O(1) per query
Space Complexity
O(N)
Extra prefix array of size N
Section 06

2D Prefix Sum 🗺️

Same idea, extended to 2D grids! Leetcode and interviews love 2D problems. Master this and you'll crack problems like "Range Sum Query 2D" in one attempt.

The 2D Formula (Inclusion-Exclusion)

2D Prefix Build
prefix[i][j] = matrix[i][j] + prefix[i-1][j] + prefix[i][j-1] - prefix[i-1][j-1]
2D Range Query (r1,c1) to (r2,c2)
sum = prefix[r2][c2] - prefix[r1-1][c2] - prefix[r2][c1-1] + prefix[r1-1][c1-1]

This is the inclusion-exclusion principle. You're adding three rectangles and subtracting the part you double-counted.

Inclusion-Exclusion Explained Visual
Full rectangle (0,0)→(r2,c2) minus top strip (0,0)→(r1-1,c2) minus left strip (0,0)→(r2,c1-1) plus top-left corner (0,0)→(r1-1,c1-1) that was subtracted twice.

Java Code for 2D

Java
public class PrefixSum2D {

    static int[][] prefix;

    public static void build(int[][] matrix) {
        int m = matrix.length, n = matrix[0].length;
        prefix = new int[m + 1][n + 1]; // 1-indexed
        for (int i = 1; i <= m; i++) {
            for (int j = 1; j <= n; j++) {
                prefix[i][j] = matrix[i-1][j-1]
                             + prefix[i-1][j]
                             + prefix[i][j-1]
                             - prefix[i-1][j-1];
            }
        }
    }

    // Query: sum of submatrix (r1,c1) to (r2,c2) — 0-indexed
    public static int query(int r1, int c1, int r2, int c2) {
        return prefix[r2+1][c2+1]
             - prefix[r1][c2+1]
             - prefix[r2+1][c1]
             + prefix[r1][c1];
    }
}
Section 07

Must-Solve Prefix Sum Problems 🔥

These are the exact problems I'd tell you to solve before any interview. Start with Easy, get the pattern, then attack Medium. Each problem teaches you a different way prefix sum is hidden inside it.
1. Range Sum Query — Immutable (LC 303)
Easy
Pattern: Direct application of prefix sum.
Key insight: Build prefix in constructor. Answer each query in O(1).
Gotcha: Handle L == 0 edge case carefully.
2. Subarray Sum Equals K (LC 560)
Medium
Pattern: Prefix Sum + HashMap (count of prefix sums seen so far).
Key insight: sum(L,R) = K → prefix[R] - prefix[L-1] = K → look for prefix[R] - K in the map.
Frequency: ⭐⭐⭐⭐⭐ — Asked in FAANG constantly.
3. Range Sum Query 2D (LC 304)
Medium
Pattern: 2D Prefix Sum with inclusion-exclusion.
Key insight: The 4-term formula. Same idea as 1D, extended to a rectangle.
4. Product of Array Except Self (LC 238)
Medium
Pattern: Left prefix product + Right suffix product.
Key insight: result[i] = left[i] × right[i]. No division needed. O(1) extra space is the follow-up.
5. Maximum Subarray Sum (Kadane's — LC 53)
Medium
Pattern: Prefix sum min tracking OR Kadane's algorithm.
Key insight: maxSum ending at R = prefix[R] - min(prefix[0..R-1]). See the connection!
6. Longest Subarray with Sum K (GFG)
Medium
Pattern: Prefix Sum + HashMap (first occurrence index).
Key insight: If prefix[R] - K exists in map at index j, length = R - j. Store only first occurrence to maximize length.
Section 08

Quiz Yourself 🧠

Acha bhai, ab check karo kitna samajh aaya! If you can answer these without looking up anything, you've understood prefix sum properly.
Q1. For arr = [2, 4, 1, 6, 3], what is prefix[3]?
A) 7
B) 13
C) 6
D) 10
prefix[3] = arr[0]+arr[1]+arr[2]+arr[3] = 2+4+1+6 = 13. Always count from index 0!
Q2. Using prefix = [2, 6, 7, 13, 16], what is sum(L=1, R=3)?
A) 13
B) 7
C) 11
D) 6
sum(1,3) = prefix[3] - prefix[0] = 13 - 2 = 11. Remember: L-1 = 0 here, so we subtract prefix[0].
Q3. Time complexity of answering Q range sum queries with prefix sum precomputation?
A) O(N×Q)
B) O(N + Q)
C) O(N log Q)
D) O(Q log N)
O(N + Q) — O(N) to build, then O(1) × Q for all queries. This is why prefix sum beats brute force O(N×Q) completely.
Q4. What is the "1-indexed trick" used for in prefix sum?
A) Saves memory
B) Faster build time
C) Eliminates the L==0 edge case
D) Works for 2D grids only
By using prefix[0] = 0 as a sentinel, the formula prefix[R+1] - prefix[L] works for ALL values of L including L=0, so you never need an if-check.
