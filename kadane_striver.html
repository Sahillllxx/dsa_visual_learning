Maximum Subarray

Given an integer array nums, find the contiguous subarray (containing at least one element) that has the largest sum and return its sum.

Example: nums = [-2, 1, -3, 4, -1, 2, 1, -5, 4] → Output: 6 (subarray [4, -1, 2, 1])

Bhai, pehle problem ko acchi tarah samjho. Hume poora array nahi lena — ek subarray lena hai jo contiguous ho (elements adjacent hon) aur uska sum maximum ho. Negative values bhi hain — wahi to cheez complicated karti hai!

What is a Subarray?

A subarray is a contiguous portion of an array. For [1, 2, 3]: valid subarrays are [1], [2], [3], [1,2], [2,3], [1,2,3]. NOT [1,3] — that's a subsequence, not a subarray.

Why is it tricky?

With all positives, the answer is always the whole array. But with negatives, you have to decide: do I include a negative number hoping the next positive compensates?

Brute Force
O(n²) and O(n³) — understand why they fail, then appreciate Kadane

Striver always says — pehle brute force socho, phir optimize karo. Agar directly Kadane yaad karo bina brute soche toh interview mein ek baar bhool jaoge aur sab khatam. Pattern samjho!

O(n³) — Try Every Subarray + Sum Each

// Fix start i, fix end j, sum from i to j
int maxSum = Integer.MIN_VALUE;

for (int i = 0; i < n; i++) {
    for (int j = i; j < n; j++) {
        int sum = 0;
        for (int k = i; k <= j; k++) {
            sum += nums[k];  // recompute every time 😞
        }
        maxSum = Math.max(maxSum, sum);
    }
}
// Time: O(n³) — TLE on n > 1000

O(n²) — Better: Carry Running Sum

// Fix start i, extend end j while accumulating
int maxSum = Integer.MIN_VALUE;

for (int i = 0; i < n; i++) {
    int sum = 0;
    for (int j = i; j < n; j++) {
        sum += nums[j];   // build sum incrementally — better!
        maxSum = Math.max(maxSum, sum);
    }
}
// Time: O(n²) — still fails on n > 10,000
Both approaches generate every possible subarray. For n = 10⁵ (LeetCode constraints), O(n²) = 10¹⁰ operations. That's ~10 billion. The judge will reject it. We need O(n).
The key question → Can I decide whether to include the current element in my window — without restarting the entire calculation — just by knowing one variable?

Kadane's answer: YES. Just track the running current sum. If it goes negative, drop everything and start fresh.
Build the Intuition
The "Reset" insight — why we throw away a negative prefix

Yeh wali insight sabse important hai. Agar mera current sum negative ho gaya, toh main usse aage carry kyun karunga? Wo aage aane wale elements ko aur kamzor bana dega! Toh main reset kar deta hoon zero pe — fresh start. Bas yahi Kadane hai.

The "Drag" Analogy

Think of running a race carrying a heavy bag. The bag is your current subarray sum. If the bag becomes a negative weight — it's actually slowing you down. So you drop it and run free. Starting fresh (sum = 0) is always better than carrying a negative burden.

The One-Line Rule

At every element: curSum += nums[i]
If curSum < 0 → reset curSum = 0 (drop the negative prefix)
Always: maxSum = max(maxSum, curSum)

Why does this work? (Proof by intuition)

Any optimal subarray has a start and an end. At the start of the optimal subarray, the running sum before it was either zero or we just reset. Why? Because if the running sum before it was positive, it would have been included in the optimal subarray. If it was negative, we reset — which is exactly what Kadane does. ✓

Kadane's Code
Pseudocode → Java — line by line explanation

Ab code likhte hain. Pehle pseudocode, phir Java. Notice karo kitna clean hai — sirf ek loop, do variables. Yahi to beauty hai Kadane ki. Interview mein yeh 5 lines likhoge aur interviewer impress ho jayega!

Pseudocode

// Kadane's Algorithm — Pseudocode
curSum  = 0
maxSum  = -INFINITY   // handles all-negative arrays

for each num in nums:
    curSum  = curSum + num           // extend current window
    maxSum  = max(maxSum, curSum)    // update global best
    if curSum < 0:
        curSum = 0                   // reset — negative prefix is useless

return maxSum

Java Implementation

public int maxSubArray(int[] nums) {
    int curSum  = 0;
    int maxSum  = Integer.MIN_VALUE; // handles all-negative

    for (int num : nums) {
        curSum += num;
        maxSum  = Math.max(maxSum, curSum);

        if (curSum < 0) {
            curSum = 0; // discard negative prefix
        }
    }
    return maxSum;
}

Java — With Subarray Indices (Bonus!)

public int maxSubArrayWithIndices(int[] nums) {
    int curSum = 0, maxSum = Integer.MIN_VALUE;
    int start  = 0, ansStart = 0, ansEnd = 0;

    for (int i = 0; i < nums.length; i++) {
        curSum += nums[i];

        if (curSum > maxSum) {
            maxSum   = curSum;
            ansStart = start;   // record window start
            ansEnd   = i;       // record window end
        }
        if (curSum < 0) {
            curSum = 0;
            start  = i + 1;     // next window starts after reset
        }
    }
    // subarray is nums[ansStart..ansEnd]
    return maxSum;
}

Maximum Product Subarray — The Twist

Unlike sum, with products a negative × negative = positive. So we must track both the maximum and minimum at each step, because a minimum (most negative) might become maximum when multiplied by a negative number ahead. 
public int maxProduct(int[] nums) {
    int maxProd = nums[0];
    int curMax  = nums[0];   // track max ending here
    int curMin  = nums[0];   // track min ending here (for neg×neg)

    for (int i = 1; i < nums.length; i++) {
        int tmp = curMax;
        curMax = Math.max(nums[i], Math.max(curMax*nums[i], curMin*nums[i]));
        curMin = Math.min(nums[i], Math.min(tmp*nums[i],   curMin*nums[i]));
        maxProd = Math.max(maxProd, curMax);
    }
    return maxProd;
}

Circular Subarray — The Elegant Trick

// Max circular subarray sum
// Answer is either: normal kadane, OR totalSum - minSubarraySum
public int maxSubarraySumCircular(int[] nums) {
    int totalSum = 0;
    int maxSum   = nums[0], curMax = 0;
    int minSum   = nums[0], curMin = 0;

    for (int num : nums) {
        curMax   = Math.max(curMax + num, num);
        maxSum   = Math.max(maxSum, curMax);
        curMin   = Math.min(curMin + num, num);
        minSum   = Math.min(minSum, curMin);
        totalSum += num;
    }
    // if all negative, circular trick gives 0 (wrong) — use maxSum
    return (maxSum > 0) ? Math.max(maxSum, totalSum - minSum) : maxSum;
}
